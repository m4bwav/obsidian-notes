# Lint a markdown folder for Obsidian and GitHub without Obsidian running

## Problem
A folder of agent-written markdown had to be checked for Obsidian and GitHub at once: broken links, wikilinks that two files could satisfy, orphans, folders with no index, frontmatter that would not parse.

## Dead ends
- Obsidian's own CLI (`obsidian links`, `obsidian backlinks`) needs the app running and enabled in Settings > General; on this machine the CLI was not yet on PATH (`vault_lint.py --probe` reports `cli_on_path: null`), so it cannot be the headless check.
- Counting a subfolder as "without an index" whenever it lacked its own README or INDEX flagged every everlast doc set, whose single root INDEX.md links every entry; the rule now counts a folder as covered when an index anywhere above links all of its files.
- A freshly written INDEX.md was itself an orphan and a duplicate basename (fixed the same day, C-20260918-2); `--fix-index` now links it from the parent index (unless that index is generated by everlast) and index names are exempt from the duplicate check.

## Fix
`python skills/obsidian-notes/scripts/vault_lint.py <folder>` (stdlib). `--fix-index` writes INDEX.md only where missing; `--to-markdown-links` rewrites unambiguous wikilinks and leaves embeds and ambiguous names alone; `--vault-init` writes the Obsidian app.json config and the gitignore lines.

## Verified by
2026-09-18 on the fixture (`errors 2: broken md links 1, ambiguous wikilinks 1`, exit 1), on two everlast doc sets, one of them inside a Unity repository (`errors 0`, no false index warnings), on a 632-file tree of AI-tooling repositories (16 broken links in old session transcripts, 54 duplicate basenames from public/private repository pairs), and by the skill's first test run (T-20260918-1: the action case ran the script four times and produced both index files).
